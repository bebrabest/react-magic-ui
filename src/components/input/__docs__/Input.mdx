# Input

`Input` is the library's styled text-entry primitive. It keeps the glass shell, forwards refs to the native `<input>`, and preserves standard HTML input behavior.

## Example

<Canvas of={Input.Default} />

## Usage

```tsx
import "react-magic-ui/style.css";
import { Input } from "react-magic-ui";
import { useState } from "react";

export function Example() {
  const [value, setValue] = useState("");

  return (
    <Input
      type="password"
      size="medium"
      placeholder="Enter your password"
      value={value}
      onChange={(event) => setValue(event.target.value)}
    />
  );
}
```

## Props

- **size** _`"small" | "medium" | "large"`_ — Control height and spacing.
- **enableClickAnimation** _`boolean`_ — Enables the surrounding glass click animation. Defaults to `true`.
- **type** _`React.HTMLInputTypeAttribute`_ — Forwarded to the native input. Defaults to `"text"`, but values like `password`, `email`, and `number` are preserved.
- **disabled** _`boolean`_ — Disables the native input.
- **className** _`string`_ — Additional classes for the input element.
- Native input props such as `value`, `defaultValue`, `onChange`, `placeholder`, `name`, `autoComplete`, `aria-*`, and `required` are forwarded.

## Behavior notes

- Refs point at the real `<input>`, so focus management and form-library integration work as expected.
- Because this wraps a native input, labels should be provided the normal HTML way with `<label htmlFor="...">` or `aria-label` / `aria-labelledby`.
- The component no longer forces `type="text"`, so specialized input modes are safe to use.

## Good fits

- Auth forms
- Search or filter controls
- Settings panels where consistent glass styling matters
